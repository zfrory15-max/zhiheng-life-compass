## 自动测试与迁移结果

运行命令：

```bash
python -m unittest discover -s tests -v
```

10 项测试涵盖卡片数量与结构、来源只保留元数据、无原始语料文件、本地 Markdown 链接与锚点、默认只检索知识卡、拒绝原文检索、无关编程请求的空结果，以及六主题各两条查询的目标卡召回。

检索检查中发现并修正了“可迁移能力”对应 CAR02、“沉没成本”对应 FIN06 的召回问题，修正后上述测试全部通过。这里的召回结论限于 12 条预设查询，不能解释为任意表述都能正确找到卡片。

迁移验证使用已构建的 25 文件 ZIP，解包至“公开版迁移 中文 空格”目录，并从其他工作目录运行测试，仍为 10 项全部通过。这验证了被测包的路径处理与资源读取，不等于所有操作系统、Python 版本或导入器都已覆盖。

Markdown 链接与锚点检查确认了无需脚本即可进入主题文件的阅读路径；本次没有创建真正不含 Python 的宿主环境，因此只记录为静态验证。

76 条旧版原句的精确匹配检查没有发现保留。该结论只针对指定检查集，不是对全部可能相似表达的穷尽检查，也不是版权授权或法律认定。公开版仍不能在包内核对原课原句。

## Codex CLI 实际调用

本次使用只读模式，以 `codex exec -C` 显式指定公开仓库目录，并要求只读取该目录的技能与参考资料。启动脚本、命令事件和最终回答已在本地交叉核对；含本机路径的运行日志未纳入公开仓库。

输入情境为：行政工作 8 年，想转项目协调岗，每周可投入 6 小时，需要维持当前收入，不接受借贷或立即裸辞；比较“留岗补技能”和“内部申请协作项目”，给出一周行动，并说明能否提供课程原话。

实际观察到：

- 读取公开目录的 `SKILL.md`、主题入口、分析方法、边界说明、职业主题与检索脚本。
- 实际执行 `scripts/search.py`，限定 `career` 主题；返回 `edition: public`、`search_mode: cards_only`。
- 比较两个方案的收益、代价、依赖条件、可逆性和调整信号，保留维持收入、不借贷与不立即裸辞的约束。
- 给出三个一周行动，时间为 1.5、2、2.5 小时，合计 6 小时。
- 使用实际读到的 CAR02、CAR03、CAR07，并区分卡片概括与情境练习；明确不能提供或核验课程原话。
- 进程退出码为 0，耗时 215.6 秒。运行期间出现连接重试并回退至 HTTP，最终完成；该耗时不是稳定性能基准。

这是一条信息充分的职业场景实测，不是六主题对话行为的完整评估。它尚未覆盖信息不足时的澄清、危机场景、操控请求、隐私处理或多轮一致性，也没有验证安装后的同名技能自动发现。
